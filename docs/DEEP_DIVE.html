ΔWhat's changed since the prior deep dive

~20 merged PRs reshape several layers. The headline items:

Wire-level fixes

  • FDCAN1 std-only (#236) — hardware filter rejects all extended frames at FIFO entry
  • HAL_FDCAN_AddMessageToTxFifoQ DataLength fix (#238) — the spurious << 16 was queuing malformed frames
  • RX DataLength fix (#243, CRITICAL) — the spurious >> 16 was mis-counting bytes
  • HSE 25 → 24 MHz (#233) — matches the actual crystal on the carrier; clocks now correct

FSM & safety

  • PrechargeMaxMs + TransitionHoldMs deadlines removed (#244) — Precharge waits indefinitely for V_target; freshness predicates are the failsafe
  • g_force_error_request now a real HIL setter — was dead hook in first deep dive
  • GPIO_PULLDOWN on TSMS + DASH_CHG (#230) — defaults to "not pressed" if disconnected

LTC chain

  • LTC6820 SPI framing single HAL call + RDCVA warm-up (#216) — the cell-V poll no longer races the wake-up
  • SPI1 MasterSSIdleness 00 → 04 → 07 CYCLE (#220 / #223) — timing margin for the chain
  • Per-IC PEC error counter (#258 / #269) — saturating u8 surfaced via two pit-diag frames

New surface

  • Pit-diag CAN stream (#247 / #248 / #257) — 49 frames covering all 95 cells + 200 temps + FSM + timing + balance + boot + post-mortem, gateable via magic payload
  • AMS_HIL_CLEAR_ERROR_LATCH (#226) — second HIL flag independent of AMS_BMS_HIL_STUB
  • firmware_info from CMake (#252) — semver + git hash + node ID baked at build time
  • can-spec/ DBC database (#255) — machine-readable CAN map for the pit-debug tool

Constant naming convention: the entire codebase moved away from kXxx to Xxx. References below use the new names; e.g. SafetyPeriodMs, CellUVmV, AmsNodeId, events::safety::CloseAirN.

Two HIL flags now

AMS_BMS_HIL_STUB still does both "stub the BMS data" AND "clear ErrorLatch each boot". AMS_HIL_CLEAR_ERROR_LATCH (PR #226) is the second half on its own — for real-LTC bench rigs against the Pico emulator that need to recover from transient discovery glitches without a debugger. Either flag triggers the clear; only the stub flag also fakes BMS data.

FDCAN1 is standard-only now

PR #236 flipped the global filter from FDCAN_ACCEPT_IN_RX_FIFO0 on extended to FDCAN_REJECT. Nothing the firmware listens for is 29-bit — VCU 0x100, boot-trigger 0x002, pit-diag 0x7F0 all fit in 11 bits, and the legacy 0x18FF50E7 charger-detect was retired in fix/48. Rejecting at the HW gate keeps the RX ISR off junk frames.

Priority discipline

Only MainTask writes relay GPIO. Only MainTask and App_InitTask refresh IWDG. Producer tasks all run at strictly lower priority, so they cannot preempt the safety supervisor.

MainTask body — one timeline

for (;;) {
  osDelayUntil(last_wake += config::SafetyPeriodMs);   // 10 ms
  now = osKernelGetTickCount();

  bms_snap     = BmsService::instance().snapshot();
  cur_snap     = CurrentService::instance().snapshot();
  veh_snap     = VehicleService::instance().snapshot();
  tsms         = HAL_GPIO_ReadPin(TSMS_GPIO_Port, TSMS_Pin) == GPIO_PIN_SET;
  dash_chg     = HAL_GPIO_ReadPin(DASH_CHG_GPIO_Port, DASH_CHG_Pin) == GPIO_PIN_SET;

  #if defined(AMS_BMS_HIL_STUB)
  force_error  = g_force_error_request;        // HIL backdoor for Block B/C tests
  #else
  force_error  = false;                         // no flight-side setter
  #endif

  fault = error_latched_ || safety::evaluate_fault({...});
  if (fault) {
    if (!error_latched_) latch_error_();    // open relays + set ErrorLatch
    Watchdog::refresh();
  } else if (now - last_state_tick >= 20) {  // FSM cadence
    if (state == Start && mode_locked == Undecided && tsms && dash_chg) {
      mode_locked = vcu_fresh ? Mode::Car : Mode::Charger;
      g_mode_locked_telemetry = (uint8_t)mode_locked; // for pit-diag
    }
    out = fsm::step({state, bms_snap, cur_snap, veh_snap,
                      tsms, dash_chg, mode_locked, force_error, now, state_entry_tick});
    apply_relay_actions(out.safety_flags);
    state = out.next;
    Watchdog::refresh();
  } else {
    Watchdog::refresh();
  }

  if (now - last_telemetry_tick >= 500) {
    send_telem(0x4A0, encode_status(...));
    send_telem(0x4A1, encode_pack(...));
    send_telem(0x4A2, encode_temps(...));
  }
}

§43 services — lock-free single-writer

Three singletons wrapping volatile structs. Cortex-M7 32-bit aligned R/W are atomic. Reader may see a one-iteration-stale snapshot — predicate tolerates it.

BmsService

writer: BmsPollTask

readers: MainTask, AcuCanTask, BalanceController

PR #250: module_online_mask now reflects current freshness, not ever-online. A module that goes silent for > BmsStaleMs drops out of the mask, so the predicate sees the failure even if the module was healthy earlier.

CurrentService

writer: CurrentSensorTask

readers: MainTask, BmsPollTask, AcuCanTask

Holds filtered_mA, last_update_tick, sensor_fault. The orphan charger_detected setter from fix/48 is the last dead remnant.

VehicleService

writer: AcuCanTask

readers: MainTask, AcuCanTask (pit-diag read)

Holds dc_bus_V, last_dc_bus_tick. start_button field still present but path is dead since fix/48 retired 0x600.

§5FSM — major simplification in PR #244

Both timed deadlines retired. PrechargeMaxMs and TransitionHoldMs are gone — Precharge waits indefinitely for V_target; Transition is a single-step passthrough. The supervisor's freshness predicates (BMS / VCU / current staleness) are now the only failsafe against a stuck contactor or lost sensor — and they already trip in < 1.5 s, so the old deadlines were redundant.

§6Safety predicates

Pure logic, evaluated every 10 ms in MainTask. Boot grace gates everything data-dependent for the first 2 s.

if (force_error_set)                                return true;   // immediate (HIL setter only)
if (now_tick < config::SafetyBootGraceMs)          return false;  // 2000 ms

// BMS — module_online_mask is current-freshness since PR #250
if (bms.module_online_mask != config::AllModulesMask)     return true;
for (m in 0..5) if (stale > config::BmsStaleMs=1500)   return true;
if (cell V outside [CellUVmV=2800, CellOVmV=4200])        return true;
if (cell T outside [CellUTC=-10, CellOTC=60])             return true;

// Current
if (current.sensor_fault)                                 return true;
#if !defined(AMS_BMS_HIL_STUB)                                       ← gated since PR #182
if (current stale > config::IStaleMs=200)                 return true;
#endif
if (|filtered_mA| > config::ImaxMa=200000)                return true;

// VCU heartbeat
if (vehicle stale > config::VcuStaleMs=200)               return true;
return false;

force_error_set is wired now

The "legacy hook with no live setter" from the first deep dive is now real. g_force_error_request (HIL_STUB-only, in safety_task.cpp) is the writable backdoor — Block B/C/D bench tests flip it via SWD / GDB / CAN backdoor to short-circuit the predicate to true on the next 10 ms tick. Flight builds have no writable path; the constant is false.

HIL stub bypass

Under -DAMS_BMS_HIL_STUB the entire BmsPollTask body is compiled out and replaced with a 250 ms loop calling BmsService::seed_for_hil_stub(now). No SPI, no LTC, no balancing. The safety predicate sees the seed values and lets the FSM leave Start.

§11NEWPit-diag CAN stream (PRs #247 / #248 / #257 / #258 / #269)

A gateable diagnostic stream surfacing the entire pack state on FDCAN1 — used by the pit-debug tool to show real-time cell-V / cell-T / FSM / balance / boot context. Disabled by default; the pit-tool sends a magic-payload command to enable.

49 + 8 frames in a 1 Hz burst

PR #263 added a yield between frames so the FDCAN1 TX FIFO can drain (16-deep). Without that, a 50+ frame burst at startup would overflow and drop the trailing diag frames. AcuCanTask sleeps briefly between batches.

Why this matters

The pit-tool can now show all 95 cell voltages and 200 NTC temperatures on a live UI, without SWD, without a logic analyser, on a stock CAN interface. The same stream surfaces the boot context (so post-fault analysis works without a debugger probe), the per-IC PEC counter (so chain hardware issues localise to a specific LTC), and the balance DCC mask (so balancing behaviour is observable on the wire).
